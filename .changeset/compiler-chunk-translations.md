'@generaltranslation/compiler': minor

Add the experimental `experimentalChunkTranslations` option (or the `GT_CHUNK_TRANSLATIONS` environment variable) for production builds of single-page apps on `gt-react` with Vite, Rollup or Rolldown. One build then serves every locale without loading a locale's whole catalog: the build reads the translation files at `files.gt.output` and writes the translations of each JavaScript chunk into a JSON file per locale next to the chunk, named after the chunk with the locale and a token that changes whenever that locale's files do, so the files can be cached as immutable and no JavaScript file changes when a translation does. The entry chunk and its static imports share one file per locale, which a script added to `index.html` requests while the page is parsed, together with the files of the chunks the page preloads with `modulepreload` links; each dynamic import requests the files of the chunks it loads while they download and runs them once the files have arrived, so a module that reads a translation as it is evaluated gets it. Which files an import needs is in the entry's file, not in the JavaScript, so an import costs a page no more than without the option. A page in the default locale requests none. `<T>` and `t` templates from `gt-react/unstable` are split by chunk. The app's `loadTranslations` is not called in such a build, which takes it out of the options `initializeGTSPA` is called with, so the catalogs it imports are not chunks of the build and no JavaScript file names them: the translations of messages that are not split, such as `msg`, the stable `useGT()` and `t()`, and dictionaries, go into one more file per locale, which the page requests with the entry's file and gt-react reads as its catalog, and the build reports how many they are. The build also writes `gt-chunk-translations.json` into its assets directory, which lists the file of each chunk and locale and holds the startup script for apps that write their own HTML.

`experimentalChunkTranslationsNaming: 'map'` (or `GT_CHUNK_TRANSLATIONS_NAMING=map`) names each chunk's file by the hash of its own content instead, with one small map of those hashes per locale that the page requests first. A changed translation then renames only the file it is in and the locale's map, and the files of chunks are requested once the map has arrived.
